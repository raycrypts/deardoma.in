# venture

tin.computer-style marketing project for dear domain, on the main
branch next to the spec. plain files with git history. this folder is
compose-only: nothing here ships, posts, or changes any live surface
without the owner's explicit approval. drafts arrive as commits for
review, never as actions.

contents:

- standalone.md: the positioning page for dear domain
- problems.md: the pains a buyer can name in a sentence, each with
  the answer
- features.md: the feature list, written against the problems
- socialcommerce.md: the funnel, the pricing position, the moat,
  the wedge icp

product sources: donna-spec.md (this branch), the donna branch (the
agent backend: src/core/negotiation.ts, src/core/contact-routes.ts,
src/core/intents.ts, src/core/state-machine.ts) and the domainhacks
branch (the hack finder: src/core/hack-fit.ts, src/core/candidates.ts,
research/). the spec section or file path is cited at each claim.
outside claims (broker minimum fees, platform policy, bot law) are
marked "needs verification" or "needs full read before publishing"
until checked against primary sources.

the moat, in one line: the acquisition industry prices every owner
like a professional squatter; the typical owner is a person with one
domain and a mild case of forgetting, and finding out which one you
are talking to is the whole product.

house rules: prose lowercase, no emojis, no em dashes, exact case
preserved in identifiers and urls. the brand is "dear domain" and the
agent is "donna"; the brand's own address is a config value
({brand_domain}) and the copy never depends on its spelling
(donna-spec.md §1).
